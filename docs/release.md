# 릴리스 확인 목록과 롤백

`/adk:release` 가 성숙도 `ga` 기준으로 쓰는 확인 목록과 롤백 절차다.

## 1. 태그 전 확인

- `main` 최신 CI(`verify`·`review`) 통과
- `TradeLedger.toc` 의 `## Version` 이 이번 태그 번호와 같음, `## Interface` 가 현재 Retail 빌드와 같음 → 다르면 CurseForge 업로드 준비가 실패한다
- `CHANGELOG.md` 에 이번 버전 절(`## [X.Y.Z]`)이 있음 → CurseForge 업로드의 changelog 가 이 절이다
- `sh .github/spec-trace.sh` 의 `M MANUAL` TC 마다 이번 태그 대상 커밋으로 게임 내 확인한 방법과 결과 → 하나라도 비면 태그를 만들지 않는다

## 2. 게임 내 확인 (태그 대상 커밋)

- 확인 환경: Retail 클라이언트, 애드온만 켠 상태와 평소 애드온 구성 둘
- Lua 오류 표시를 켠다: `/console scriptErrors 1` → 아래 항목 중 오류 창이 뜨면 실패
- 거래 알림은 실제 채팅으로 나간다 → 거래 상대는 본인의 다른 캐릭터나 미리 알린 상대로 하고, 채널은 귓속말·파티로 시작한다

| 항목 | 확인 |
| --- | --- |
| 로드 | 로그인·`/reload` 후 오류 없음, 로드 메시지, 애드온 목록의 아이콘·버전 |
| 거래 완료 알림 | 아이템·골드를 주고받은 거래 완료 → 켠 채널마다 보낸 것·받은 것 한 줄 |
| 거래 취소 알림 | 상대 취소·본인 취소·창 닫기 각각 → 켠 채널에 취소 한 줄 |
| 거래 요청 알림 | 받은 거래 요청 → 대화창에 요청 알림 (켠 경우만) |
| 금액 기준 경고 | 기준 이상 골드 거래 → 화면 경고, 기준 미만 → 경고 없음 |
| 장부 | 완료·취소 거래가 장부 목록에 남고 상세가 맞음, 전체 삭제 |
| 자동 메시지 | `/tl add` 로 추가·편집·삭제, 켠 항목이 간격마다 지정 채널로 전송, 끄면 멈춤 |
| 설정 | `/tl` 로 설정 패널, 값 변경이 `/reload` 후 유지, 초기화 |
| 언어 | koKR·enUS 클라이언트 문구 |

## 3. 이전 버전에서의 업데이트

- 직전 릴리스 버전으로 설정·장부·자동 메시지를 만든 `TradeLedgerDB` 가 있는 상태에서 새 버전을 설치해 2를 확인한다.
  - 새 설치(빈 DB)만으로 확인하면 공허하다 → 기존 데이터의 호환이 이 항목의 대상이다.
- `TradeLedgerDB` 의 구조를 바꾸는 릴리스는 이전 버전 코드가 새 구조를 읽어도 오류 없이 동작해야 한다 → 아래 롤백이 데이터 손상 없이 가능해야 하기 때문이다.
  - 지킬 수 없으면 노트 맨 위에 "이전 버전으로 되돌리면 {무엇}이 사라짐" 을 적고, 롤백 전에 `WTF/Account/<계정>/SavedVariables/TradeLedger.lua` 백업을 안내한다.

## 4. 롤백

배포한 파일은 업로드 API 로 지우거나 되돌릴 수 없고, 공개 태그는 이미 받은 사용자가 있다 → 되돌리기는 **이전 내용을 담은 새 patch 버전을 앞으로 배포**하는 것이다.

1. 문제 버전 `vX.Y.Z` 와 마지막 정상 버전 `vA.B.C` 를 정한다.
2. 이슈를 만들고(bugfix), 워크트리에서 문제 변경을 되돌린다.
   - 일부만 문제면 해당 커밋만 `git revert`, 전부면 `git diff vA.B.C vX.Y.Z` 의 역을 적용한다.
   - `TradeLedger.toc` 의 `## Version` 을 `X.Y.(Z+1)` 로, `CHANGELOG.md` 에 "vX.Y.Z 의 {변경} 되돌림" 절을 추가한다.
3. 일반 PR 절차(검증·리뷰·merge)를 거친다 → 롤백도 `main` 이력에 남아야 다음 릴리스가 문제 변경을 다시 싣지 않는다.
4. `/adk:release X.Y.(Z+1)` → `/curseforge:deploy vX.Y.(Z+1)` 로 배포하고 1~3을 확인한다.
5. 문제 버전 정리
   - GitHub 릴리스 `vX.Y.Z`: 태그는 지우지 않고 노트 맨 위에 "철회: vX.Y.(Z+1) 사용" 을 적는다 (`gh release edit`).
   - CurseForge 의 `vX.Y.Z` 파일: 업로드 도구로는 바꿀 수 없다 → 저장소 소유자가 웹 UI(Files 탭)에서 처리한다.
