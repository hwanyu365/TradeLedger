# 거래 결과 알림 스펙

## 1. 개요

| 항목 | 값 |
| --- | --- |
| 문서명 | spec_trade_alert |
| 작성일 / 최종 수정일 | 2026-11-14 / 2026-11-14 |
| 버전 | 1.0 |
| 기준 커밋 ID | d0dd1ce |

- **기능명:** 거래 완료·취소·요청 알림, 금액 기준 경고 (UC1)
- **목적 (Why):** 거래가 끝난 즉시 주고받은 내용을 상대·파티·길드에 남겨, 거래 내용을 두고 말이 엇갈리지 않게 한다.

## 2. 목표 및 범위

### In Scope

- 플레이어 간 거래창 1회의 상태 추적, 완료·취소 판정과 채팅 알림
- 거래 요청 알림(본인 대화창), 기준 금액 이상 거래의 화면 경고
- 장부 저장 호출 (저장 규칙은 `spec_trade_history.md`)

### Out of Scope

- 우편·경매장·NPC 상점 거래
- 본인 대화창에 완료·취소 결과 출력 → 현재 출력하지 않는다 (#28)

## 3. 요구사항

### 3.1 사용자 스토리

- `US#1` [as-built] 다른 플레이어와 거래하는 플레이어로서, 거래 내용을 두고 말이 엇갈리지 않기 위해, 거래 결과가 자동으로 상대와 일행에게 알려지기를 원한다 → FR#1~FR#8

### 3.2 기능 요구사항

- `FR#1` [as-built] 거래창이 열리면 거래창의 상대 이름을 거래 상대로 잡는다. 이름이 비어 있으면 `Unknown` 이다.
- `FR#2` [as-built] 거래 중 아이템 슬롯(1~7)과 양쪽 골드가 바뀔 때마다 따라간다. 양쪽이 모두 수락하면 아이템이 있는 슬롯과 양쪽 골드를 다시 읽는다.
  - 비어 있는 슬롯은 다시 읽을 때 지우지 않는다 → 슬롯 변경 이벤트로만 비워진다.
- `FR#3` [as-built] 양쪽 수락 뒤 거래창이 닫히면 완료로 한 번 처리한다.

  ```
  Given  완료 알림 켜짐, 상대 Bob, 귓속말 채널만 켜짐(기본값)
  When   양쪽 수락 → 거래창 닫힘
  Then   Bob 에게 완료 문구 귓속말 1건, 금액 경고 판정(FR#7), 장부에 성공 1건
  Given  완료 알림 꺼짐
  When   같은 거래
  Then   채팅 알림·금액 경고·장부 저장 모두 없음 (#20)
  ```

- `FR#4` [as-built] 취소는 한 거래에 한 번 처리한다.

  ```
  When   거래 취소 이벤트
  Then   즉시 취소 문구를 알리고 장부에 실패 1건
  When   양쪽 수락 없이 거래창이 닫힘
  Then   0.1초 뒤, 그 사이 취소 이벤트가 없었으면 취소로 처리
  When   취소 알림 꺼짐
  Then   채팅 알림·장부 저장 모두 없음 (#20)
  ```

- `FR#5` [as-built] 알림은 켠 채널 중 조건이 맞는 곳으로만 보낸다. 순서는 길드 → 파티 → 공격대 → 귓속말이다.

  | 채널 | 보내는 조건 | 기본 |
  | --- | --- | --- |
  | 길드 | 길드 소속 | 끔 |
  | 파티 | 그룹 중 (공격대 포함) | 끔 |
  | 공격대 | 공격대 중 | 끔 |
  | 귓속말 | 거래 상대 이름이 `Unknown` 이 아님 → 상대에게 | 켬 |

  - 본인 대화창에는 출력하지 않는다 (#28).
- `FR#6` [as-built] 채팅 문구 형식
  - 완료: `[TradeLedger] {상대}: {보냄}({목록}) / {받음}({목록})`
  - 취소: `[TradeLedger] ` + 로케일의 거래 취소 문구(상대 이름 포함)
  - 목록: 슬롯 1~7 의 아이템을 순서대로, 링크가 있으면 링크·없으면 이름, 수량이 2 이상이면 ` x{수량}`, 골드가 있으면 끝에 금액. 비어 있으면 로케일의 "없음" 문구
  - 금액: `{g}g{s}s{c}c`, 0 인 단위는 생략, 0 이면 금액 없음
- `FR#7` [as-built] 금액 경고: 설정이 켜져 있고 기준이 0 보다 크며, 완료 거래에서 한쪽 골드가 기준(골드) 이상이면, 공격대 경고 영역에 두 골드 중 큰 금액으로 경고한다. 취소 거래는 경고하지 않는다.
- `FR#8` [as-built] 거래 요청 알림을 켜면, 거래 요청을 받았을 때 요청자 이름을 본인 대화창에 출력한다. 기본은 꺼짐이다.

## 4. 데이터 및 API 스펙

## 6. 동작 로직 및 정책

### 6.1 거래 상태 [FR#1~FR#4]

```
닫힘 --TRADE_SHOW--> 진행(상대·슬롯·골드 초기화)
진행 --슬롯·골드 변경--> 진행 (FR#2)
진행 --양쪽 수락--> 수락됨(아이템 있는 슬롯·골드 다시 읽음)
수락됨 --창 닫힘--> 완료 처리 → 닫힘 (FR#3)
진행 --취소 이벤트--> 취소 처리 → 닫힘 (FR#4)
진행 --창 닫힘--> 0.1초 대기 --취소 이벤트 없음--> 취소 처리 → 닫힘
```

- 닫힘 상태의 창 닫힘·취소 이벤트는 무시한다 → 한 거래가 두 번 처리되지 않는다.

### 6.2 설계 결정

| 결정 | 선택 | 기각한 대안 | 근거 |
| --- | --- | --- | --- |
| `D#1` | 양쪽 수락 시 아이템이 있는 슬롯과 골드를 다시 읽는다 | 변경 이벤트로 모은 값만 쓴다 | 추가·변경 이벤트를 놓쳐도 수락 시점의 아이템·골드로 알린다. 비워진 슬롯은 이벤트에 맡긴다 [FR#2] |
| `D#2` | 수락 없이 창이 닫히면 0.1초 뒤 판정한다 | 창 닫힘에서 바로 취소 처리 | 창 닫힘과 취소 이벤트가 함께 올 때 한 번만 처리한다 → 먼저 처리한 쪽이 상태를 닫는다 [FR#4] |
| `D#3` | 완료·취소 처리 안에서 장부 저장까지 한다 | 장부 저장을 알림 설정과 분리 | as-built. 알림을 끄면 장부도 빠지는 결과가 결함으로 판정됨 (#20) |
